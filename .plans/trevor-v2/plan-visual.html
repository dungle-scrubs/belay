Implementation Plan

Trevor V2 - Host Rebuild on Effect

A browser-only frontend and an Effect host that are both Richter participants, communicating only through Richter's durable, ordered event log. No Rust TUI, no stdio, no direct host-web boundary.

2026-06-22 pivot. Re-pointed from the original Rust-TUI / stdio architecture to browser + Richter-participant. The RFC, spike-guide, and FEATURES.md retain the original design as historical context; this plan supersedes it.
01

Architecture

apps/web

React 19 + Vite + Effect. The renderer; owns presentation. WS participant.

apps/agent-host Slice 1+

Node + Effect. Agent loop, provider adapters, tools. WS participant.

WebSocket  /sessions/{id}/stream  -  replay-then-tail

Richter

Durable session service. Generic, unmodified - trevor attaches as a participant. REST /sessions, /sessions/{id}/events.

durable substrate (Postgres)  |  local Docker :3025  |  prod mac-mini over Tailscale

Transport - D-014

Replay-then-tail over WS; publish via REST POST /events (S0), then the WS publish command. Host drains user.message events, publishes assistant/tool events.

Protocol - D-017

Re-owned in Effect Schema, grown one event at a time. Trevor's semantic events ride as opaque payloads inside Richter sessionEvents; Richter stays generic.

Participants - D-019

Capability-scoped. Exactly one filesystem-authority runtime per session (lightweight control lease). Browser clients and future observers are first-class, lease-free.

Stack - D-001 / D-018

Effect v3 for the control plane and decode boundary. pnpm + Node/tsx workspace (Biome, Lefthook, tsc, Vite). Greenfield, not a port - no conformance oracle.

02

Phases

Phase 0 - Foundations

Done

pnpm workspace (Biome, Lefthook, tsc, Vite, React 19, Effect 3); tsc --noEmit clean, vite build green. Richter substrate running in Docker on :3025; schema migrated; durable event round-trip verified.

Phase 1 - Browser-first slices

In progress

Four vertical slices that walk from a pure browser durability proof up to a real multi-provider turn. Each adds exactly one capability.

S0 - browser ↔ Richter In progress

Durability proof

apps/web connects to a session, replay-then-tail, renders the event log, publishes a user.message. Reload reconnects and replays. No host, no model.

S1 - host ↔ Richter echo

Host joins as participant

Minimal agent-host joins the same session; on each user.message it publishes a canned agent.output. Establishes the emit -> appendEvent choke point and participant identity/lease.

S2 - real turn via LM Studio

First real completion

Echo becomes a real completion against LM Studio qwen3.6-27B, streamed as assistant.delta* -> assistant.completed. Validates A-004 (fiber interrupt tears down the stream).

S3 - pi-ai + provider switch

Multi-provider main role

Add the pi-ai adapter -> GPT-5.5 and a provider setting. Main role = ordered array [local qwen, GPT-5.5], offline -> local fallback.

Phase 2+ - Host feature backlog

Backlog

FEATURES.md section 4 (H-001…H-174: session/run/turn lifecycle, agent loop, tools, routing, persistence-in-Richter, settings, auth, prompt-production, doctor, workspace, shell interpolation H-175) remains valid as the post-S3 backlog, re-sequenced onto the Richter transport. Multi-user features stay dropped; the capability-scoped filesystem lease (D-019) is the only authority mechanism.

05

Risks

Richter coupling

Trevor depends on a running Richter. Mitigated by Docker-local dev and Richter being generic - no trevor-specific changes, it attaches as a participant.

pi-ai interruption leak - D-010

Validated at S2; fallback is race-and-abandon + per-runId post-cancel delta suppression.

Effect-dialect drift

Keep Effect to justified boundaries (Schema decode, host control plane); plain React/TS elsewhere so the Effect island does not fight React.
